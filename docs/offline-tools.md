# Offline bench helpers

Electronics, Byte Lab, Subnet Lab, and [Resistor Lab](resistor-lab.md) work without Wi-Fi, microSD, or an attached device. Open them from the launcher. They do not open a bus, enable an output, or save files. Inputs remain available when returning Home and reopening the app during the same boot; restarting the tablet restores the examples.

[RTU Frames](modbus-rtu.md) is another offline helper: build a Modbus read request with CRC for Serial's Hex input, or decode a captured reply. Its firmware build and initial ST7121 example/handoff checks pass; see its separate verification notes for remaining coverage.

## Electronics

Choose a calculator, tap a value to edit it with the on-screen keyboard, and tap Calculate. Units are shown beside every input: volts, milliamps, ohms, and microfarads. Enter resistance as a number such as `4700` rather than `4.7k`. Keys open when you tap an input or **Show keys**, and can be dismissed with the checkmark or **Hide keys**.

- **Ohm's law:** select the unknown voltage, current, or resistance and enter the other two. The result includes all three values and resistor power. For example, 3.3 V across 330 ohms gives 10 mA and 0.033 W.
- **Voltage divider:** enter supply voltage, the top resistor (supply to output), and the bottom resistor (output to ground). Results describe an unloaded divider, including output voltage, current, and resistor dissipation. A 3.3 V supply with two 10000-ohm resistors gives 1.65 V at 0.165 mA. Loading the output changes the actual voltage.
- **LED resistor:** enter supply voltage, LED forward voltage, and target current. A 5 V supply, 2 V LED, and 10 mA target require an ideal 300-ohm resistor dissipating 0.03 W. Choose an available resistor value and a power rating with suitable margin, then check the actual circuit.
- **RC filter:** enter resistance in ohms and capacitance in microfarads. The ideal low-pass circuit has a resistor from input to output and a capacitor from output to ground, with zero source impedance and no output load. Results show the time constant, cutoff frequency, 10-90% step rise time, and time to settle within 1% of the final step value. For 10000 ohms and 0.1 uF (100 nF), these are 1 ms, approximately 159.155 Hz, 2.19722 ms, and 4.60517 ms. Using capacitance in farads, the formulas are `tau = R*C`, `fc = 1/(2*pi*tau)`, `rise = ln(9)*tau`, and `settling = ln(100)*tau`. Component tolerances, source impedance, and loading affect a real circuit.

Values must be positive and within the range shown by the app. Zero, incomplete entries, unsupported number formats, and results outside the supported range produce an error instead of leaving an old result visible. Negative signs, unit suffixes, exponent notation, and pasted line breaks are preserved and rejected, so `-5` cannot silently turn into `5` or `1e3` into `13`. Overlong input remains invalid after Home/re-entry. These are ideal circuit calculations; Tab5 GPIO remains limited to 3.3 V as described in [Pin safety](pin-safety.md).

## Byte Lab

Choose Hex or ASCII to inspect a payload of up to 128 bytes, or **Number input** to encode a value. Hex accepts complete pairs such as `01 03 00 00 00 0A` or `01030000000A`, with optional whitespace between bytes. A lone nibble or invalid character is an error. ASCII uses 7-bit character values; it does not interpret escape sequences such as `\n` as control bytes. Use Hex to enter `00`, `0A`, or bytes above `7F`.

The app shows the byte count, normalized hex, a printable ASCII preview, and checksums over exactly the entered bytes. Nonprintable bytes appear as dots in the preview.

Exactly 1, 2, or 4 bytes also show unsigned and two's-complement signed integer values in big-endian (BE, most significant byte first) and little-endian (LE, least significant byte first) order. For example, `80` is unsigned 128 or signed -128, and `FF 7F` is signed -129 in BE or 32767 in LE.

Exactly 4 bytes additionally show both IEEE 754 Float32 interpretations, using nine significant decimal digits. `3F 80 00 00` is 1 in BE; `00 00 80 3F` is 1 in LE. Negative zero (`80 00 00 00` in BE), tiny subnormal values, signed infinities, and NaNs are represented explicitly. These are alternative interpretations of the same bits, not a claim about the target device's data type or register order. A 3-byte or longer-than-4-byte payload has no numeric interpretation; checksums and previews still work. Tap the payload to open the keyboard, and use Done to hide it and see all result rows.

### Encode a number

Choose **Number input**, select an unsigned/signed 8-, 16-, or 32-bit integer or **Float32**, then choose big or little endian. The preview shows the generated bytes in transmission order, and checksums cover exactly those bytes. For example:

| Input and type | Big endian | Little endian |
| --- | --- | --- |
| `165`, unsigned 8-bit | `A5` | `A5` |
| `4660`, unsigned 16-bit | `12 34` | `34 12` |
| `-1234`, signed 16-bit | `FB 2E` | `2E FB` |
| `1.5`, Float32 | `3F C0 00 00` | `00 00 C0 3F` |

Integers require decimal digits, with an optional leading `+`; signed types also accept `-`. The selected type's exact limits appear above the input. Fractions, exponents, and `0x` prefixes are rejected for integer types. Values outside the selected range produce an error instead of wrapping.

Float32 accepts a decimal fraction and optional exponent, such as `0.1`, `-2.5e3`, or `1e-45`. The result shows the value after rounding to Float32 precision; for example, `0.1` displays as `0.100000001`. Representable subnormal values and negative zero are preserved. A finite decimal that overflows or a nonzero number that rounds to zero is rejected. The exact special tokens `Inf`, `+Inf`, `-Inf`, and `NaN` encode infinities or the quiet-NaN pattern `7FC00000`; the number keyboard provides these tokens. No spaces, line breaks, unit suffixes, lowercase special tokens, or NaN payload syntax are accepted. Numeric input is limited to 32 characters, with invalid and overlong drafts retained for rejection after Home/re-entry.

Tap **USE AS HEX (replaces Hex draft)** to transfer the generated bytes into the Hex editor. This replaces that draft, preserves the Number and ASCII drafts, and sends nothing to a device. The button is disabled for invalid input. Hex, ASCII, and Number drafts, number type, and byte order stay in RAM through Home/re-entry; a restart restores the defaults. **EXAMPLE** supplies a value for the selected type, while **CLEAR** empties the current draft. Check the device's data type and byte/register order before using the bytes in a protocol tool.

### Move bytes between apps

**Copy bytes** places the current valid Hex, ASCII, or encoded Number payload in a shared 128-byte RAM clipboard. **Paste hex** replaces only the Hex draft and switches to that editor; Number and ASCII drafts remain available. **Clear copy** clears the shared clipboard without changing any draft. Copying invalid input is disabled and preserves the previous copy. An intentionally copied empty payload is distinct from a cleared clipboard.

In [UDP Console](udp-console.md), **PASTE BYTES** prepares the Hex draft and clears any pending send confirmation. A separate SEND/CONFIRM action transmits it. **COPY REPLY** copies the complete original response if it has 0-128 bytes; larger or truncated replies cannot replace the clipboard. Return to Byte Lab and **Paste hex** to inspect its values and checksums.

In [MQTT Console](mqtt-console.md#prepare-a-byte-payload), **PASTE BYTES** captures a separate 0-128-byte draft and selects **PAYLOAD: BYTES**. Review its Hex view, topic, QoS and retain choice before the explicit **PUBLISH** tap. **PAYLOAD: TEXT** returns to the current text draft. Later clipboard changes do not replace prepared bytes or a queued publish. **COPY RX** copies the latest complete 0-128-byte receive for Byte Lab; partial or oversized receives preserve the clipboard. Prepared bytes stay in RAM through Home and clear on restart.

In SPI Console, **PASTE BYTES** accepts 1-32 copied bytes and replaces the transmit draft. Empty or larger copies leave the draft unchanged. SPI must still be started explicitly and **TRANSFER** tapped. Copying and pasting never open a socket, start a bus, or send data. The clipboard survives Home, clears on restart, and is not saved to flash or SD.

Tap SPI's TX field for hex keys, spaces, cursor movement and backspace. Enter complete whitespace-separated byte pairs, up to 95 characters. The checkmark closes the keyboard without starting or sending; **TRANSFER** remains explicit. The transmit draft survives Home in RAM, including invalid characters, line breaks and the first character beyond the limit, so rejected input cannot silently become a valid prefix on reopening. **CLEAR TX** clears only this draft. A restart clears it.

After a successful SPI transfer, **COPY RX** copies all 1-32 received bytes into that clipboard for **Paste hex** in Byte Lab. The saved result includes the original TX/RX bytes, mode, and clock, and survives Stop/Home independently of the next transmit draft or selected settings. SPI receives one byte per transmitted byte; this includes any dummy or command-phase bytes returned by the peripheral. **CLEAR RESULT** clears only this saved transfer. Invalid drafts preserve the identified previous result; an actual driver transfer failure clears it and disables copying. Neither clear nor a failed copy changes the existing clipboard. The result stays in RAM until cleared, replaced by another transfer, or restarted.

In I2C Inspector, select **One-shot bytes** from 1 to 32, then tap **READ ONCE**. The transaction sends one 8-bit register pointer followed by a repeated-start read of the selected length. The target determines whether it advances registers, wraps or returns FIFO data; check its datasheet. No per-byte register addresses are inferred. **READ ONCE** stops Watch and finishes any CSV capture before reading, so a timer cannot replace the new result. The selected length stays in RAM through Home.

**COPY READ** exports all received bytes, with no formatting or truncation. The saved address, register pointer, speed and bytes remain visible through Home and later setting changes. Return to Byte Lab and **Paste hex** to inspect integers, Float32 values or checksums. Watch and CSV retain their one-byte, 1 Hz behavior regardless of the one-shot length; starting Watch replaces the saved result each sample. A failed read (including failure to clean up that transaction) or confirmed write attempt clears the saved read and disables copying. **CLEAR READ** clears only the result, leaving the clipboard and CSV capture alone; an active Watch can populate it again. Scan, read, capture, length changes, copy and clear actions cancel pending write confirmation. Opening the inspector starts no scan: tap **SCAN** explicitly.

The register driver releases its device and bus after each transaction. Failed removals retain their handles for a later cleanup attempt; Home retries, and new transactions stop if cleanup still fails. GPIO, Scope and Servo entry, along with application-controlled restart/OTA, remain blocked while I2C owns the bus. Raw writes remain one-byte, explicitly confirmed operations.

The [Serial terminal](serial-terminal.md) also accepts copied bytes with **PASTE**, selecting Hex transmit format without an added line ending. It preserves the separate ASCII draft and requires an explicit START/SEND. Empty copies leave its draft unchanged.

Serial's **CAPTURE RX**, **FREEZE RX** and **COPY RX** controls return a manually bounded 1-128-byte receive window to the clipboard. A 129th byte or a read/drain failure prevents copying a partial window. Capture works across multiple reads, retains its source settings through Home, and does not detect protocol frame boundaries. Verify the captured bytes in Byte Lab or RTU Frames.

For saved serial logs, open the published CSV in Files, select a record on the current page, and tap **COPY ROW**. This copies its original 1-128 bytes even in escaped ASCII view; oversized records are never shortened. Return to Byte Lab and **Paste hex** to inspect them. The file remains unchanged.

In [RTU Frames](modbus-rtu.md), **COPY REQUEST** copies a validated eight-byte Modbus read frame including CRC. **PASTE REPLY** replaces the reply draft with 1-37 copied bytes; empty or larger copies preserve it. **DECODE** then checks that complete reply against the entered request. RTU Frames never starts Serial or transmits by itself.

In BLE GATT Explorer, **COPY LATEST VALUE** copies the latest received read response, notification or indication into the same clipboard. The displayed handle identifies the source even when another characteristic is selected. Copies include the entire received payload of 0-64 bytes; an intentionally empty value is a valid copy. Truncated previews and failed receive-buffer copies leave the previous clipboard unchanged. Copy cancels pending write confirmation and sends no BLE request. READ obtains one ATT response; it does not assemble a long characteristic value across multiple requests. New reads, confirmed writes and disconnect clear the previous received value, while an explicit clipboard copy survives Home. Use Byte Lab's **Paste hex** to inspect it.

On 2026-09-29, target startup self-tests passed real NimBLE buffer traversal through the read/notification callbacks and copy handler, including all sizes 0-64, an oversized value, split and short buffers, read errors, indications, stale connections and disconnect. The current ST7121 session tested scanning only; live GATT copy and export remain in the hardware checklist.

### Checksums

- **SUM8:** sum modulo 256.
- **XOR8:** exclusive-or of every byte.
- **CRC-16/MODBUS:** initial value `FFFF`, reflected polynomial `A001`, no final XOR.
- **CRC-32/ISO-HDLC:** initial value `FFFFFFFF`, reflected polynomial `EDB88320`, final XOR `FFFFFFFF`.

For ASCII `123456789`, CRC-16/MODBUS is `4B37` (wire bytes `37 4B`) and CRC-32/ISO-HDLC is `CBF43926`. For the six-byte Modbus request example `01 03 00 00 00 0A`, the CRC is `CDC5` (wire bytes `C5 CD`). The app shows the low-byte-first Modbus wire order. Enter a message without its existing checksum when calculating the checksum to append.

## Subnet Lab

Enter an IPv4 address and either a prefix (`24` or `/24`) or a dotted netmask (`255.255.255.0`). Optionally enter a second IPv4 address as the peer, then tap **Calculate**. The keyboard includes dot and slash; its checkmark calculates and dismisses it. **Example** restores `192.168.1.42/24` with peer `192.168.1.100`.

The result shows the network, netmask, wildcard (inverse mask), broadcast, first and last host slots, and total/host address counts. For the default example, the network is `192.168.1.0/24`, broadcast is `192.168.1.255`, and there are 254 host slots, from `.1` through `.254`. For `10.20.30.40` with mask `255.255.240.0`, the network is `10.20.16.0/20` and broadcast is `10.20.31.255`. Use the calculated broadcast when configuring [Wake-on-LAN](device-network-tools.md), after checking the actual network mask and broadcast support.

Peer comparison identifies an address outside the subnet, a host slot inside it, or the subnet's network/broadcast address. It applies the entered mask only: it does not contact the peer, check availability, inspect the peer's own mask, or establish reachability across routing, firewalls, or VLANs.

- `/0` covers all 4,294,967,296 IPv4 addresses; the count does not overflow a 32-bit integer.
- `/31` uses the two endpoints of a point-to-point link, with no directed broadcast, following [RFC 3021](https://datatracker.ietf.org/doc/html/rfc3021).
- `/32` describes one address/host route with no directed broadcast.
- Host slots describe subnet arithmetic. Reserved, special-use, already assigned, and otherwise unavailable addresses are not removed from the count.

Addresses require four decimal octets from 0 to 255, without leading zeros, whitespace, hostnames, or an appended prefix. Put the prefix in its own field. A dotted netmask must have consecutive 1 bits followed by 0 bits; a wildcard such as `0.0.0.255` is not accepted as a netmask. Pasted line breaks remain visible and invalid rather than joining two fragments into an address or prefix. Invalid input replaces the result with an error; editing any field clears the previous calculation and comparison.

## Validation

`tools/test_offline_ui.ps1 -I2cOnly -Snapshots` checks the real I2C saved-read panel and Byte Lab handoff with cached LVGL and one compile job. It covers all lengths 1-32, `00`/`FF`/`A5`, buffer ownership, invalid lengths, original source identity, failed-read/clear invalidation, callback invocation before copy/clear, direct disabled-button events, signed/Float32 decoding, Home retention, and eight reopen cycles without heap loss. The separate `i2c_register_test.c` runs 192 read combinations across every length, three addresses and both speeds, plus invalid requests, exact writes, receive failures and retained cleanup/retry faults. These checks and the 2026-09-29 single-job ESP-IDF firmware build pass. ST7121 passed empty-bus scan/read failures, 32-byte length selection/retention, disabled copy after failure, READ ONCE stopping Watch and Home with a popup open. The native panel test does not run the full legacy screen; successful reads from a real target, CSV/confirmation faults, electrical behavior and the other panel family remain pending.

Bulk Hex paste is rendered once on the next LVGL pass. This prevents per-nibble valid/invalid changes from queuing hundreds of button animations and exhausting the fixed UI heap. Copy revalidates synchronously, and Home cancels any queued render. The host regression includes a direct 128-byte Hex paste and immediate exit before a queued render.

Clipboard host checks cover absent versus intentionally empty payloads, all 128 bytes, formatting bounds, invalid-copy preservation, clearing, Number/ASCII/Hex drafts, and Home retention. The UI runner also exercises SPI with a driver adapter: copy/paste produces no pin writes or transfers, 0/33/128-byte copies preserve its draft, invalid or overlong input never transmits, and accepted transfers reach the adapter byte-for-byte. Receive-copy checks cover RX differing from TX, one- and 32-byte results, saved source settings, Stop/Home retention, clear semantics, and a failed driver that already touched its receive buffer. Editor checks cover actual hex keys, cursor/backspace, no-send Done/Cancel, independent CLEAR TX, immediate Home with keys attached, and exact retention/rejection of invalid, excess-length and Unicode drafts. A real Byte Lab handoff decodes the copied Float32 value. `tools/test_offline_ui.ps1 -SpiOnly -Snapshots` passed these checks and eight reopen cycles without allocator loss, using one compile job and the cached LVGL library. This mode refuses a library rebuild. The 2026-09-29 firmware build passed. ST7121 accepted `AA` from the hex keyboard, kept Done separate from transfer, returned RX `00` on an unwired one-byte transfer, retained the original mode/clock after edits and copied `00` into Byte Lab. This verifies the UI handoff, not peripheral correctness or electrical timing. The earlier paste-only feature passed 100 SPI lifecycle cycles.

Pure calculation and parser tests run on the host and in CI; small known-value checks also run at firmware startup. Subnet Lab additionally cross-checks 2,112 cases covering every prefix against Python's standard-library `ipaddress` module. Byte Lab cross-checks 4,096 signed/Float32 payloads in both byte orders against Python's `int.from_bytes` and [`struct.unpack`](https://docs.python.org/3/library/struct.html). Its encoder checks 7,272 integer/Float32/order cases against independent integer serialization and exact rational rounding, including overflow, underflow, and halfway cases. RC checks cover known component pairs, exponential settling, invalid inputs, and overflow/underflow. Resistor Lab independently checks 1,056 EIA-96 combinations plus band roles, tolerances, and malformed markings. The optional `tools/test_offline_ui.ps1 -Snapshots` uses real LVGL widgets to check calculations, invalid input, keyboard actions, Number-to-Hex transfer, input retention, and 100 open/close cycles per app. These host checks passed for all four apps with no allocator loss or increase in live allocations, and the ESP-IDF 5.4.2 firmware build passed. On 2026-09-29, ST7121 rendered all four apps offline, passed the default Electronics/Subnet/Resistor calculations and Byte Lab CRC/number checks, and returned Home. The remaining input, lifecycle and second-panel coverage is tracked in the [hardware smoke checklist](hardware-smoke-checklist.md).
